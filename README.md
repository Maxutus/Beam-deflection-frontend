# Расчёт прогиба балки – фронтенд

Учебный проект по курсу «Разработка интернет-приложений», ИУ5-55Б.

Ветка `lab7-pwa-https` развивает интерфейс гостя и создателя из шестой лабораторной. Для локального запуска данные берутся из веб-сервиса ([Beam-deflection-backend](https://github.com/Maxutus/Beam-deflection-backend), ветка `lab4-auth-swagger`). Если он недоступен, гостю показываются mock-данные. Сборка для GitHub Pages всегда работает с mock.

## Задание

Расчёт прогиба балки. `Услуги` – балки (деревянные, металлические, железобетонные) с фото, видео, нагрузкой и прогибом. `Заявка` – черновик новой балки, который создатель заполняет и публикует в ленту.

## Стек

- React 19, TypeScript, Vite
- React Router (`react-router-dom`)
- React-Bootstrap (`Navbar`, `Nav`, `Card`, `Form`, `Button`, `Alert`, `Spinner`)
- Redux Toolkit (`createSlice`, `createAsyncThunk`, `configureStore`), `react-redux`
- axios, кодогенерация API из Swagger (`swagger-typescript-api`)

## Роли

- **Гость** – смотрит плитку и ленту, фильтрует балки по прогибу.
- **Создатель** – после входа дополнительно добавляет и публикует балки, удаляет свои балки и ставит лайки.

## Страницы

### Плитка – `/beams`

Список опубликованных балок (`GET /api/beams` при локальном запуске). Плитка показывает от одной до четырёх колонок в зависимости от ширины.

| Элемент | Что делает |
|---|---|
| Логин в заголовке | Показывается после входа |
| Поле «Прогиб до, мм» | Максимальный прогиб для фильтра. Значение хранится в Redux и сохраняется при переходе между страницами |
| Кнопка «Найти» (или Enter) | Запрос `GET /api/beams?max_deflection=…`. Пустое поле – все балки |
| «Найдено балок: N» | Сколько балок показано |
| Карточка балки | Фото, прогиб, название, число лайков. Клик открывает балку в ленте |
| Кнопка с корзиной на карточке | Только у своих балок создателя (`is_mine = 1`). Удаляет балку: `DELETE /api/beams/:id` |

### Лента – `/beams/feed` и `/beams/feed/:id`

Одна балка на весь экран (`GET /api/beams/feed`). Стартовая страница: с адреса `/` происходит переход сюда. Без `id` – первая опубликованная балка, с `id` – балка с этим номером.

| Элемент | Что делает |
|---|---|
| Видео | Проигрывается автоматически, без звука, по кругу |
| Название, «Прогиб», «Нагрузка» | Параметры балки |
| Кнопка «больше / меньше» | Разворачивает и сворачивает описание |
| Кнопка с сердцем | Число лайков. Создатель ставит и снимает лайк: `POST /api/beams/:id/like` с `like` 1 или 0. У гостя кнопка выключена |
| Кнопка со стрелкой | Следующая балка: `GET /api/beams/feed?id=…&next=true`. После последней – снова первая |

### Добавление – `/beams/draft`

Доступна только создателю, у гостя – переход на страницу входа. При открытии загружается черновик текущего пользователя (`GET /api/beams/draft`).

Шаг 1 – черновика нет (метка «новая»):

| Поле или кнопка | Что делает |
|---|---|
| Изображение | Выбор фото нажатием на квадрат, сразу показывается превью |
| Видео | Выбор видео нажатием на квадрат, сразу показывается превью |
| Название | Название балки |
| Далее | Создаёт черновик: `POST /api/beams` с названием, фото и видео (multipart) |

Шаг 2 – черновик есть (метка «черновик»): фото и видео черновика из MinIO, название только для чтения.

| Поле или кнопка | Что делает |
|---|---|
| Описание | Как балка ведёт себя под нагрузкой |
| Нагрузка, кН/м | Нагрузка на балку |
| Прогиб, мм | Прогиб балки |
| Опубликовать | `PUT /api/beams/draft/publish`, затем переход в ленту на опубликованную балку |

### Вход – `/login`

| Поле или кнопка | Что делает |
|---|---|
| Логин, Пароль | Данные пользователя |
| Войти | `POST /api/users/login` через axios, JWT сохраняется в localStorage, логин – в Redux, переход на плитку |

Ошибка входа показывается над формой.

### Несуществующий адрес

Сообщение «Страница не найдена» и кнопка «К списку балок».

## Навбар

| Пункт | Гость | Создатель |
|---|---|---|
| Лента | Ведёт на `/beams/feed` | То же |
| Добавление | Выключен | Ведёт на `/beams/draft` |
| Плитка | Ведёт на `/beams` | То же |
| Вход / Выход | «Вход» – страница входа | «Выход» – `POST /api/users/logout`, JWT удаляется, Redux возвращается в состояние гостя, фильтр сбрасывается |

Во время любого запроса поверх страницы показывается анимация загрузки, кнопки заблокированы.

## Redux

`src/store.ts` – хранилище из трёх слайсов:

| Слайс | Состояние | Действия |
|---|---|---|
| `beams` | `searchValue` (фильтр), `beams` (плитка), `feedBeam` (лента), `loading`, `error` | `setSearchValue`; thunk `getBeamsList`, `getFeedBeam`, `likeBeam`, `deleteBeam` |
| `draft` | `draft`, `loading`, `error` | thunk `getDraft`, `createDraft`, `publishDraft` |
| `user` | `login`, `isAuthenticated`, `error` | `setUser`, `resetUser`, `setError` |

- Запросы по балкам выполняются в `createAsyncThunk` через сгенерированный API (`api.beams.beamsList`, `api.beams.feedList`, `api.beams.beamsCreate`, `api.beams.draftList`, `api.beams.draftPublishUpdate`, `api.beams.likeCreate`, `api.beams.beamsDelete`).
- Вход и выход – только axios прямо в компонентах (`LoginPage`, `TabBar`), результат передаётся в Redux через `dispatch(setUser(...))` и `dispatch(resetUser())`, без thunk и кодогенерации.
- JWT хранится только в localStorage. После F5 Redux возвращается в состояние гостя, токен в localStorage остаётся.
- Если веб-сервис недоступен, thunk завершается `rejected`, и для гостя в `extraReducers` подставляются балки из `src/modules/mock.ts` с тем же фильтром. Создателю показывается ошибка.

## Прокси

CORS решён проксированием через сервер Vite (`vite.config.ts`):

| Адрес на фронтенде | Куда проксируется |
|---|---|
| `/api/...` | веб-сервис `http://localhost:8080/api/...` |
| `/media/...` | MinIO `http://localhost:9000/media/...` |

Веб-сервис отдаёт полные адреса фото и видео (`http://localhost:9000/media/…`), фронтенд превращает их в `/media/…`, чтобы они шли через прокси.

## Запуск

1. Запустить веб-сервис (ветка `lab4-auth-swagger`), PostgreSQL, MinIO и Redis.
2. Установить зависимости и сгенерировать API из Swagger (`http://localhost:8080/swagger/doc.json`):

```bash
npm install
npm run generate-api
npm run dev
```

Приложение открывается на http://localhost:3000.

Через Docker (веб-сервис и MinIO доступны по `host.docker.internal`):

```bash
docker compose up --build
```

### Гостевая PWA и GitHub Pages

```bash
npm ci
npm run build:pages
npm run preview:pages
```

Локальная копия Pages открывается на `http://localhost:4173/Beam-deflection-frontend/`. В этой сборке доступна только гостевая навигация, а запросы списка и ленты сразу используют mock. `BrowserRouter` получает базовый путь репозитория, а `404.html` позволяет GitHub Pages открыть внутренний адрес при прямом переходе. `vite-plugin-pwa` создаёт манифест и Service Worker, который кэширует сборку, изображения и видео. В DevTools во вкладке Application проверь Manifest и дождись статуса Activated перед проверкой в авиарежиме.

Для публикации выполни `npm run deploy` из ветки `lab7-pwa-https`. Команда соберёт гостевую версию и отправит содержимое `dist` в ветку `gh-pages`. В **Settings → Pages** выбери **Deploy from a branch**, ветку `gh-pages` и каталог `/ (root)`.

### HTTPS на ноутбуке и телефоне

Запусти Go-сервис на порту 8080 и его хранилища по инструкции бэкенда. Для уже настроенной базы в каталоге `backend` выполни `docker compose up -d postgres minio redis` и `go run ./cmd/rip`. Во фронтенде команда `npm run dev:https` подключает `vite-plugin-mkcert` и включает PWA в режиме разработки. При первом запуске плагин может запросить установку локального центра сертификации.

Если сертификат для IP ноутбука выпущен вручную через `mkcert`, укажи его файлы явно. Подставь текущий IP ноутбука в Wi-Fi.

```bash
LAN_IP=192.168.1.20
mkdir -p .certs
mkcert -install
mkcert -cert-file .certs/lan.pem -key-file .certs/lan-key.pem localhost 127.0.0.1 "$LAN_IP"
HTTPS_CERT_FILE=.certs/lan.pem HTTPS_KEY_FILE=.certs/lan-key.pem npm run dev:https
```

На телефоне в той же сети установи доверие к публичному сертификату `rootCA.pem` из каталога плагина `.certs`. Для сертификата, выпущенного вручную, этот файл лежит в каталоге, который выводит `mkcert -CAROOT`. На iOS включи полное доверие к нему в настройках доверия сертификатам. Открой `https://<IP-ноутбука>:3000`. Vite принимает запросы по HTTPS и передаёт `/api` в Go, а `/media` в MinIO. Приватные ключи остаются на ноутбуке.

### Контрольные вопросы

- **Flux.** Данные движутся в одном направлении. Интерфейс отправляет действие, состояние обновляется, интерфейс получает новое состояние и перерисовывается.
- **Redux.** Store хранит состояние. `dispatch` отправляет action с типом и данными. Reducer вычисляет следующее состояние. В проекте слайс `beams` хранит фильтр по прогибу. Переход со страницы списка на страницу балки и обратно сохраняет его, поскольку обе страницы используют один store.
- **PWA, Tauri и нативное приложение.** PWA устанавливается из браузера, манифест задаёт способ запуска, а Service Worker позволяет обслуживать запросы офлайн. Tauri запускает веб-интерфейс в системном WebView и связывает его с нативным кодом. Нативное приложение использует SDK конкретной платформы и может обращаться к её возможностям напрямую.
- **GitHub Pages.** Статический хостинг для готовой сборки фронтенда. Для проекта это отдельная сборка с mock-данными; Go, PostgreSQL, Redis и MinIO работают на ноутбуке в локальном сценарии.
