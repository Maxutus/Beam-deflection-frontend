# Расчёт прогиба балки – фронтенд

Учебный проект по курсу «Разработка интернет-приложений», ИУ5-55Б.

Дополнительное задание «Индексы в БД», ветка `db-indexes`. В плитке добавлена серверная пагинация, а лента загружается из подборки в Redis. Для показа используется ветка `db-indexes` репозитория [Beam-deflection-backend](https://github.com/Maxutus/Beam-deflection-backend).

## Задание

Расчёт прогиба балки. `Услуги` – балки (деревянные, металлические, железобетонные) с фото, видео, нагрузкой и прогибом. `Заявка` – черновик новой балки, который создатель заполняет и публикует в ленту.

## Стек

- React 19, TypeScript, Vite
- React Router (`react-router-dom`)
- React-Bootstrap (`Navbar`, `Nav`, `Card`, `Form`, `Button`, `Alert`, `Spinner`, `Pagination`)
- Redux Toolkit (`createSlice`, `createAsyncThunk`, `configureStore`), `react-redux`
- axios, кодогенерация API из Swagger (`swagger-typescript-api`)

## Роли

- **Гость** – смотрит плитку и ленту, фильтрует балки по прогибу.
- **Создатель** – после входа дополнительно добавляет и публикует балки, удаляет свои балки и ставит лайки.

## Страницы

### Плитка – `/beams`

Список опубликованных балок. Фронтенд отправляет `page`, `limit=8` и выбранный `max_deflection` в `GET /api/beams`. Из `total` рассчитывается число страниц. Плитка показывает от одной до четырёх колонок в зависимости от ширины.

| Элемент | Что делает |
|---|---|
| Логин в заголовке | Показывается после входа |
| Поле «Прогиб до, мм» | Максимальный прогиб для фильтра. Значение хранится в Redux и сохраняется при переходе между страницами |
| Кнопка «Найти» (или Enter) | Применяет фильтр и открывает первую страницу. Пустое поле показывает все балки |
| «Найдено балок: N» | Общее число балок, прошедших фильтр |
| Переключатель под плиткой | Текущая страница, число страниц и переход к первой, предыдущей, следующей или последней странице. На странице до восьми карточек |
| Карточка балки | Фото, прогиб, название, число лайков. Клик открывает балку в ленте |
| Кнопка с корзиной на карточке | Только у своих балок создателя (`is_mine = 1`). Удаляет балку: `DELETE /api/beams/:id` |

### Лента – `/beams/feed` и `/beams/feed/:id`

Одна балка на весь экран (`GET /api/beams/feed`). При загрузке приложения `POST /api/beams/feed/session` подготавливает в Redis подборку для сессии браузера. Без `id` лента открывает первую балку подборки. Переход из плитки открывает балку по её `id`.

| Элемент | Что делает |
|---|---|
| Видео | Проигрывается автоматически, без звука, по кругу |
| Название, «Прогиб», «Нагрузка» | Параметры балки |
| Кнопка «больше / меньше» | Разворачивает и сворачивает описание |
| Кнопка с сердцем | Число лайков. Создатель ставит и снимает лайк: `POST /api/beams/:id/like` с `like` 1 или 0. У гостя кнопка выключена |
| Кнопка со стрелкой | Следующая балка по порядку в Redis через `GET /api/beams/feed?id=…&next=true`. После последней сервер формирует новую подборку |

### Добавление – `/beams/draft`

Доступна только создателю, у гостя – переход на страницу входа. При открытии загружается черновик текущего пользователя (`GET /api/beams/draft`).

Шаг 1 – черновика нет (метка «новая»):

| Поле или кнопка | Что делает |
|---|---|
| Изображение | Выбор фото нажатием на превью |
| Видео | Выбор видео в блоке под изображением |
| Название | Название балки |
| Далее | Создаёт черновик: `POST /api/beams` с названием, фото и видео (multipart) |

Шаг 2 – черновик есть (метка «черновик»): фото и видео черновика из MinIO, название только для чтения.

| Поле или кнопка | Что делает |
|---|---|
| Описание | Как балка ведёт себя под нагрузкой |
| Нагрузка, кН/м | Нагрузка на балку |
| Прогиб, мм | Прогиб балки |
| Опубликовать | `PUT /api/beams/draft/publish`, затем переход в ленту на опубликованную балку |

### Вход – `/login`

| Поле или кнопка | Что делает |
|---|---|
| Логин, Пароль | Данные пользователя |
| Войти | `POST /api/users/login` через axios, JWT сохраняется в localStorage, логин – в Redux, переход на плитку |

Ошибка входа показывается над формой.

### Несуществующий адрес

Приложение открывает ленту `/beams/feed`.

## Навбар

| Пункт | Гость | Создатель |
|---|---|---|
| Лента | Ведёт на `/beams/feed` | То же |
| Добавление | Выключен | Ведёт на `/beams/draft` |
| Плитка | Ведёт на `/beams` | То же |
| Вход / Выход | «Вход» – страница входа | «Выход» – `POST /api/users/logout`, JWT удаляется, Redux возвращается в состояние гостя, фильтр сбрасывается |

Во время любого запроса поверх страницы показывается анимация загрузки, кнопки заблокированы.

## Redux

`src/store.ts` – хранилище из трёх слайсов:

| Слайс | Состояние | Действия |
|---|---|---|
| `beams` | `searchValue`, `appliedSearchValue`, `beams`, `currentPage`, `totalPages`, `total`, `listLoading`, `listError`, `feedBeam`, `loading`, `error` | `setSearchValue`, `applySearchValue`, `setCurrentPage` и thunk `getBeamsList`, `getFeedBeam`, `likeBeam`, `deleteBeam` |
| `draft` | `draft`, `loading`, `error` | thunk `getDraft`, `createDraft`, `publishDraft` |
| `user` | `login`, `isAuthenticated`, `error` | `setUser`, `resetUser`, `setError` |

- Запросы по балкам выполняются в `createAsyncThunk` через сгенерированный API (`api.beams.beamsList`, `api.beams.feedList`, `api.beams.beamsCreate`, `api.beams.draftList`, `api.beams.draftPublishUpdate`, `api.beams.likeCreate`, `api.beams.beamsDelete`).
- Вход и выход – только axios прямо в компонентах (`LoginPage`, `TabBar`), результат передаётся в Redux через `dispatch(setUser(...))` и `dispatch(resetUser())`, без thunk и кодогенерации.
- JWT хранится только в localStorage. После F5 Redux возвращается в состояние гостя, токен в localStorage остаётся.
- Если веб-сервис недоступен, гостю показываются балки из `src/modules/mock.ts` с применённым фильтром. Создателю показывается ошибка.

## Прокси

CORS решён проксированием через сервер Vite (`vite.config.ts`):

| Адрес на фронтенде | Куда проксируется |
|---|---|
| `/api/...` | веб-сервис `http://localhost:8080/api/...` |
| `/media/...` | MinIO допа `http://localhost:9100/media/...` |

Фронтенд преобразует полные адреса фото и видео в `/media/…`, чтобы запросы шли через прокси Vite.

## Запуск

1. Переключить оба репозитория на `db-indexes`. В Docker Desktop запустить группу `beams-indexes` с отдельной демобазой. Настройка новой базы описана в README ветки бэкенда.
2. В папке `backend` выполнить `go run ./cmd/rip`.
3. В папке `frontend` установить зависимости и запустить Vite.

```bash
npm ci
npm run dev
```

Плитка доступна по адресу `http://localhost:3000/beams`. Клиент Swagger хранится в `src/api/Api.ts`. После изменения API его можно обновить командой `npm run generate-api` при запущенном бэкенде.

Через Docker (веб-сервис и MinIO доступны по `host.docker.internal`):

```bash
docker compose up --build
```
